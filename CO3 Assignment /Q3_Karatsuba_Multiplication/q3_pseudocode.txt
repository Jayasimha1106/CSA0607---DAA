STANDARD MULTIPLICATION: for every digit a_i of A, multiply by every digit b_j of B -> n^2 digit mults, O(n^2).

KARATSUBA(X, Y):                           // n = max digits, m = floor(n/2)
    if n <= cutoff: return SchoolMultiply(X, Y)
    X = X1*10^m + X0 ;  Y = Y1*10^m + Y0   // split into high and low halves
    Z0 <- Karatsuba(X0, Y0)
    Z2 <- Karatsuba(X1, Y1)
    Z1 <- Karatsuba(X0 + X1, Y0 + Y1)      // 3rd (and last) recursive multiplication
    Mid <- Z1 - Z0 - Z2                    // = X0*Y1 + X1*Y0  (the 2 'cross' products obtained from 1 multiply)
    return Z2*10^(2m) + Mid*10^m + Z0

Why fewer multiplications: XY = X1Y1*10^2m + (X1Y0 + X0Y1)*10^m + X0Y0 needs 4 half-size products;
(X0+X1)(Y0+Y1) = X0Y0 + X0Y1 + X1Y0 + X1Y1, so cross terms = Z1 - Z0 - Z2 -> only 3 products
(cost: extra additions/subtractions, all O(n)).

Recurrence : T(n) = 3T(n/2) + cn
Solution   : a=3, b=2, f(n)=O(n); n^(log2 3) = n^1.585 dominates f(n) -> Master theorem case 1
             T(n) = Theta(n^(log2 3)) ~ Theta(n^1.585)   (vs Theta(n^2) for 4 subproblems)
Expansion  : T(n) = c*n*(1 + 3/2 + (3/2)^2 + ... + (3/2)^(log2 n)) = O(3^(log2 n)) = O(n^1.585)

Crossover: Karatsuba's extra additions, digit-list copying/padding, and recursion calls cost more than
the n^2 loop saves when n is small; use a hybrid (switch to school multiplication below a cutoff).

JOINT CONCLUSION: Big-O hides constants and lower-order terms. T_K(n)=c1*n^1.585 beats T_S(n)=c2*n^2 only
when n > (c1/c2)^(1/0.415). With c1 > c2 (recursion, additions, memory allocation) small inputs favour the simple method.
